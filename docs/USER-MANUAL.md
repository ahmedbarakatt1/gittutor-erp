# Git Tutor user manual

**21 November 2026 · Production and testing edition**

Use this guide to request tutoring with your own course material, teach a session, support a family or run the service. All amounts are Egyptian pounds (EGP). Appointment times use Cairo time unless a field explicitly says it uses your device's time.

## 1. Choose your site and workspace

| Site | When to use it | Start here |
| --- | --- | --- |
| Production | Invited team members managing their actual accounts. The site is team-protected. Commercial policy, upload processing, live scheduling and recovery checks remain launch dependencies. | [Production sign-in](https://gittutor-erp-production.vercel.app/login) |
| Testing | Practice with the account and example booking assigned to you. The preview contains imported operating history. Use practice materials and simulated payments. | [Testing sign-in](https://gittutor-erp-rho.vercel.app/login) |

**First sign-in.** Open the latest Git Tutor invitation in the mailbox it was sent to. Check Spam if necessary. Complete the verification and password setup in that message. Production may first ask you to sign in to Vercel. If your Vercel account lacks access, ask the owner to arrange access to the protected site. If the invitation has expired, request a fresh invitation. For a forgotten password, use the recovery link on the sign-in screen and complete the newest recovery email.

**Find your starting point.** The workspace menu shows destinations available to the signed-in account. On a phone, tap **Menu**, select a page and use the page title to confirm where you landed. Use separate browser profiles when practicing as different people. On a shared device, select **Sign out** when finished.

| I am… | Open | My usual first action |

The links in the rest of this manual open production. To practice, open the testing sign-in above and use its menus. Account references, course files, bookings and balances belong to the site where they were created.

## 2. Request tutoring and upload study material

Visitors can read [Subjects](https://gittutor-erp-production.vercel.app/subjects) and [session prices](https://gittutor-erp-production.vercel.app/offers). Subjects gives examples in Computer Science, Engineering, Business and Business Intelligence. Choose one to prefill your topic, or choose **Request help with another subject**. Available sessions, approved tutor profiles and personal records require sign-in.

| Format | EGP per learner for one 90–105 minute session |
| --- | ---: |
| Individual | 650 |
| Group of two | 575 |
| Group of three | 550 |
| Group of four | 500 |

1. Open **Request a session**. Select the learner who will attend. A guardian needs both booking and materials permissions for that learner.
2. Enter the subject or topic, course if relevant, what you need help with, preferred Egypt times and preferred format. Choose the undecided option if you want staff to recommend a format.
3. Select **Continue to upload material**. This saves a private draft. Attach at least one relevant file, such as lecture slides, a problem sheet or a screenshot. PDF, PPTX, PNG, JPEG and WebP are accepted up to 25 MiB per file.
4. Wait for the file check to finish. Remove an unsuitable file from the draft and upload a supported replacement. Submit when every retained file has passed. Reopen your request from **Requests** to see its status and the staff reply.
5. If staff ask for more information, open the request, edit the brief or attachments and resubmit it. If staff propose a session, select **Review and book this session**. A closed request keeps its outcome in your history.

**Example.** A parent requests help with a lecture on accounting, uploads the slides and asks for Wednesday evening. When a reviewer offers a specific appointment, the parent checks its start time, duration, price and named learner before reserving. The family's original preferred time was a scheduling request.

## 3. Reserve a seat, confirm it and join

1. Open the proposed session, or follow an available session link after signing in. Under **Booking for**, select the learner. Read the date, start time, duration, format, tutor and terms.
2. Acknowledge the terms and select **Reserve a temporary seat**. Open the reservation, read the exact quote, tick its consent box and choose **Accept this quote** before the deadline. Review any revised quote before accepting it.
3. Fund the seat using the displayed payment instructions or eligible package coverage. Check the booking status after payment review. For groups, confirmation can also depend on the other seats, the formation deadline and staff checks.
4. When confirmed, open the booking and find **Session room**. Select **Join session** when enabled. Use the expected Google account if Meet asks who is joining. Tutors join through their assigned session. Use the portal each time so it can check current access.

| What the screen says | What to do |
| --- | --- |
| Temporary seat or quote awaiting acceptance | Read the expiry and respond. If it expired, check availability again. |
| Full or waiting | Join the waitlist for the named learner if offered. Watch updates and act before a seat offer expires. You can leave the queue. |
| Accepted or forming | Check remaining balance, package coverage and group status. Plan around the session once it says **Confirmed**. |
| Preparing room | Use **Refresh meeting status**. If class is near, send support the booking reference and scheduled time. |
| Room needs attention or access revoked | Verify the account and booking. Staff can check the organizer or issue replacement access. |
| Practice room | **Preview simulated meeting** opens a practice screen. A live room displays Google Meet and **Join session**. |

**Change or cancel.** Open the relevant booking and choose **Request a change**, or **Release temporary seat** if offered. Read the proposed timing, tuition difference, deadline and remedy. Each affected learner or guardian responds for that seat. Where another payer owns the funds, their separate consent may be required. Check for **Applied** or the final resolution before relying on the new arrangements. [My bookings](https://gittutor-erp-production.vercel.app/learn/bookings)

## 4. Payments, packages and refunds

**Pay an accepted charge.** In **Payments**, open the specific charge. Check the learner, purpose, amount and current collection instructions. Use the exact reference and destination shown for that charge. In the testing site use the assigned practice evidence. Upload the receipt as PDF, PNG, JPEG or WebP, up to 5 MiB. Wait for its check, select the prepared evidence and choose **Submit receipt for review**. Open the receipt to track it. [Payments](https://gittutor-erp-production.vercel.app/learn/payments)

**Understand the balance.** A receipt shows what the payer reported. Staff independently verify the money that reached the receiving account and apply it to the charge. Look for the allocated amount and remaining balance. For split funding, excess funds or a proposed payment plan, the source owner reviews what will be applied to which charge. Reopen the original charge and receipt before sending a second transfer.

**Use a package.** In **Packages**, choose the learner and read the approved contract, price, minutes per credit, eligible offers and expiry. Select **Accept terms and create purchase** and fund its charge. Purchased credits become usable after full settled payment. When booking, inspect the eligible coverage and any cash top-up. Package detail shows available, reserved, used and expired credits, movements and their origin. A renewal or restoration follows the terms shown on that package. [Packages](https://gittutor-erp-production.vercel.app/learn/packages)

**Track a refund.** Open **Refunds** for the payer's eligible requests. Open the linked record, check the proposed remedy and provide any requested destination details through the private form. If a transfer or refund appears unresolved, give staff its reference. Bank settlement, account credit and restored package entitlement are distinct outcomes. Confirm the outcome on the relevant balance or package record. [Refunds](https://gittutor-erp-production.vercel.app/learn/refunds)

## 5. Files, grades and family access

**Prepare for class.** Open the booking's private preparation area to share study material with the assigned tutor. Use the class resources section for handouts the tutor has published. Open **Study files** and choose the session to find accessible resources. A request attachment, session preparation file, quiz and payment receipt each belong in their own form. Downloads may require a fresh access check. Reopen the original portal record if an old link expires. [Learning files](https://gittutor-erp-production.vercel.app/learn/files)

**Read your grades.** Open **Quizzes and grades**, find the assigned quiz and select **Download PDF**. Check the title and session before starting work. Ask the tutor how to return answers when needed. The dashboard displays published points against the maximum. **Awaiting grade** means the tutor has yet to publish a score. A published zero is a score. After a correction, refresh the page. A class summary and individualized feedback may also appear on the completed booking once published. [Quizzes and grades](https://gittutor-erp-production.vercel.app/learn/grades)

**Give a guardian access.**

1. From their verified account, the guardian privately shares their **verified contact reference** with the learner.
2. The learner opens **Guardian access**, enters that reference, selects permissions and an invitation expiry, and chooses **Create invitation**. Set profile, booking, payments, materials and notification permissions according to what this guardian needs.
3. The guardian signs in to their own account, enters the invitation reference and single-use code, and chooses **Accept invitation**. Refresh the account and confirm the intended learner appears under **Your learners**.
4. A guardian acting for siblings checks the learner selected each time. To end access, the learner uses **Revoke guardian access**. Expired or revoked permissions can affect bookings, file downloads and notifications.

**Know which reference to share.** Account reference identifies the signed-in person. Learner reference identifies the individual receiving teaching. Verified contact reference identifies a contact for a relationship invitation. A booking or payment reference identifies one transaction. Share the reference requested by the specific form through a private channel.

## 6. Instructor handbook

**Apply to teach.** Open **Apply to teach** with a verified account, select the subjects you teach, describe your experience and choose **Submit application**. An administrator reviews the application. After approval, sign in or refresh to find the tutor workspace. [Apply to teach](https://gittutor-erp-production.vercel.app/apply-to-teach)

**At the start of the day.** Open the tutor dashboard and select the next assigned lesson, or open **Schedule** for the full list. Check the Cairo start, format, status, available request material, class resources and room status. Maintain recurring weekly availability and dated exceptions. A dated exception replaces that day's weekly pattern. Review any proposals requiring your consent. [Tutor schedule](https://gittutor-erp-production.vercel.app/tutor/schedule)

**Share a handout.** In the assigned lesson, open **Class resources**, upload a supported teaching file and wait for **Check passed**. Select **Publish to this session**. Confirm the resource is listed as published for the intended session. For a learner's private preparation, open that learner's material inside the assignment.

**Publish a quiz and grade it.**

1. Open **Quizzes**, choose an assigned session and select **Add a PDF quiz**. Use a PDF up to 25 MiB. Upload a file or select a checked PDF for that session.
2. Enter a recognizable quiz title and maximum points. Select **Publish quiz**. Confirmed learners and their authorized guardians can now open the PDF.
3. Under **Grades**, choose the learner, enter points earned within the maximum and choose **Publish grade**. Repeat for each learner. To correct a published result, select the learner again, enter the corrected score and choose **Update grade**. Verify the selected learner and final score. [Session quizzes](https://gittutor-erp-production.vercel.app/tutor/quizzes)

**Record delivery.** In the assigned session, record the actual start, then each learner's attendance and participation. Enter the actual delivery details and choose **Submit delivery for approval**. If asked to correct the submission, reopen the session and address the review note. After approval, publish any shared class summary and private learner feedback to the correct audiences. Report unavailability, proposed replacement or other teaching issues through the teaching workspace. [Teaching operations](https://gittutor-erp-production.vercel.app/tutor/teaching)

**Profile and pay.** Use the tutor workspace to submit teaching-profile changes for review. The approved profile is the version other signed-in users can view. In the private pay workspace, check your earnings, adjustments, settled payouts and remaining payable. Provide payout destination information only in its dedicated workflow. Keep downloaded statements private. [Tutor pay](https://gittutor-erp-production.vercel.app/tutor/pay)

## 7. Customer service handbook

**Work the request queue.** On the dashboard, inspect the incoming requests and open the relevant case. Check the named learner, preferred format/times, brief and cleared files. Record a customer-facing response and move the case into review. Ask the requester for missing information, close it with an explanation, or choose an eligible future session. Review suitability, price, duration and capacity before sending a match. The customer reserves and accepts the session from the resulting link. If no eligible slot appears, ask the scheduler to check availability and publication. [Service requests](https://gittutor-erp-production.vercel.app/service/requests)

**Review a payment.**

1. Open **Payments**, select an unassigned review and use **Claim case**. Read the receipt, expected charge, amount, date and destination.
2. Find the independent incoming transfer. Compare receiving-account evidence and reference. Record settled amount and Cairo settlement time through **Verify settled funds** when supported by the independent evidence.
3. Verify the source owner's account and ownership evidence. Check the proposed allocation against the correct charge and payer. For ambiguous or shared evidence, leave the case open and escalate for reconciliation.
4. Use **Apply verified funds** for the matched transfer. Refresh the charge and confirm the applied amount and remaining balance. If a colleague holds the claim, coordinate with them. If your claim expired, reclaim the case before acting. [Service payments](https://gittutor-erp-production.vercel.app/service/payments)

**Support and follow-up.** Open the support inbox, claim or accept the assignment, read the transcript and reply. Keep private notes in their own field. Escalate or transfer with context when another team member owns the next step. Resolve the conversation after recording the outcome. In **Customers**, find the named learner, inspect their authorized history and create a follow-up with an owner, due time and channel. A shared family phone number needs identity review. [Support inbox](https://gittutor-erp-production.vercel.app/service/support) · [Customers](https://gittutor-erp-production.vercel.app/service/customers)

## 8. Owner and administrator handbook

**Owner access.** Open the **Admin dashboard** using the verified production owner account. Its management role is labelled **Administrator**. Use a separate practice learner on the testing site to try the student experience. To grant staff access to a colleague who already received an account invitation, use the verified-account procedure below. [Staff and applications](https://gittutor-erp-production.vercel.app/admin/access)

| Situation | Steps | Check the result |
| --- | --- | --- |
| Existing verified account | Ask the person to sign in and privately share the **Account reference** from their own account. Under **Grant a staff role**, enter that reference, choose Tutor, Customer service or Administrator, enter the reason and select **Grant role**. | The person refreshes or signs in again and opens their assigned workspace. |
| New staff member | Under **Invite a staff member**, enter the intended email, role, reason and expiry. Choose **Create staff invitation**. The recipient verifies their mailbox and accepts the staff invitation in the intended account. | Check acceptance and active grants. Email delivery and role activation are separate steps. |
| Staff role ends | Under **Revoke a staff role**, refresh the list, select the specific active grant, review the account and reason, and choose **Revoke role**. | The affected account's subsequent requests use its current permissions. |
| Tutor applicant | A verified applicant submits the teaching application. Review it under staff and applications, record the decision and check the resulting teaching access. Review proposed tutor profile content in the catalog separately. | Confirm the assigned teaching workspace and the approved profile each show the intended result. |

**Prepare a session for sale.** In **Catalog**, select the correct subject, format, duration and capacity. Review the draft pricing and policy, including customer terms and effective dates. Approve the intended versions and publish the eligible offer. Keep confidential teaching agreements in the privileged controls. In **Schedule**, choose the published offer, tutor and Cairo time, check availability and conflicts, set the capacity or intended group tier and prepare the required teaching agreement. Confirm the occurrence appears among the eligible choices for the requester. [Catalog](https://gittutor-erp-production.vercel.app/admin/catalog) · [Schedule](https://gittutor-erp-production.vercel.app/admin/schedule)

**Review delivery and changes.** Use the session directory to identify the exact occurrence, then review delivery, attendance and exceptions. Approve only supported facts, or return the submission for correction. Approved delivery drives the learning record and base tutor earning. Use a referenced correction for subsequent changes. For a move, group roster change or replacement instructor, review the proposed terms, capacity, consents and funding before applying the change. [Session history](https://gittutor-erp-production.vercel.app/admin/sessions) · [Teaching operations](https://gittutor-erp-production.vercel.app/admin/teaching)

| Export | Open **Exports** in your workspace. Choose an available report and filters, request it, wait for generation and download it while access is valid. **Enable Google Meet and parallel lessons.** In **Integrations**, review the provider mode, organizer and last verification. Choose **Add and verify Google account** for each additional organizer. The organizer signs in to the intended Google account and approves the requested Calendar permission. Refresh and confirm the private Meet check passed. Overlapping lessons need enough available verified organizers and an available instructor for each lesson. If capacity is exhausted, connect another eligible organizer or reschedule. Reconnect an organizer when authorization expires. Check affected lessons before revoking an organizer. [Integrations](https://gittutor-erp-production.vercel.app/admin/integrations)

**Updates and delivery.** Each workspace has its own updates inbox. Open the linked booking, payment or support record for the current state. Administrators can review pending, failed or uncertain message outcomes and recipient preferences in notification operations. Verify the provider's outcome before retrying an uncertain send. Website support threads stay in the portal. WhatsApp opens the existing business number, where staff reply manually. [Notification operations](https://gittutor-erp-production.vercel.app/admin/notifications-operations)

## 10. Common problems and support

| What you see | What to do next |
| --- | --- |
| Vercel sign-in, then Git Tutor sign-in | Complete each sign-in with its intended account. Ask the owner for production site access if the Vercel screen denies entry. |
| Wrong workspace or missing learner | Check the site, signed-in email and access. Refresh after a role change. For a guardian, confirm the named learner, accepted invitation, scope and expiry. |
| An invitation, download or meeting link expired | Open the original record and request fresh access through the portal. For account activation, ask staff for a fresh invitation. Keep single-use links private. |
| File check stays pending or fails | Keep the draft. Check the file type and size, refresh its status and contact staff if the scanner is unavailable. If a file was rejected, try a supported copy from a trusted source. |
| Receipt submitted, session still forming | Check the charge balance, review status and booking separately. Staff can investigate the transfer or outstanding group requirements. An uploaded receipt alone leaves settlement pending. |
| A save says the record changed | Refresh, read the current decision and compare it with the change you intended. Reapply only the change still needed. |
| Report looks empty or lower than expected | Check the site, workspace, learner, date range and reporting filters. Drill into the source records. Some views require linked workbook data or approved attendance. |
| Need help near the lesson start | Give staff the booking reference, Cairo start and exact status. Keep course files, receipts, passwords, one-time codes and private links in their appropriate secure channels. |
