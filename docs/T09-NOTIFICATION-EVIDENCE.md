# T09 notification foundation and executed checks

The original T04–T06 combined checkpoint remains open. Following the user's explicit request to move to remaining features, notification implementation proceeds alongside T08. This document records a foundation, not completion of the full recipient matrix or release acceptance.

## Implemented

Database routing resolves current learner, guardian scope, actual payer, tutor assignment and assigned staff queue. A unique event/account/channel/template-version identity produces separate in-app and email deliveries. Attempts and observations are distinct; historical observations are immutable. Dispatch rechecks verified contact, current authority, preferences and current reminder version. Signed callbacks are deduplicated and do not regress delivered/bounced outcomes. Hard bounce creates a contact-verification task. Only definite failures permit a new attempt; an operator may request reconciliation of an existing unknown attempt.

Strict English/Arabic templates contain a category-specific notice, current Cairo session time where appropriate and an authorized portal link. They accept neither arbitrary event JSON nor financial/private fields. Customer templates reject tutor-agreement, earning and payout categories. Private documents are never attached. Customer amounts and detailed terms remain in their authorized portal views; richer event-specific email detail is still pending the complete routing-matrix review.

The local adapter accepts only synthetic `@example.test` recipients and saves immutable-identity artifacts in `.local/email-inbox`. Unknown-after-success is reconciled from the saved identity. The live SES adapter uses pinned `@aws-sdk/client-sesv2@3.1166.0`, selected from the official package registry after consulting [AWS SDK guidance](https://docs.aws.amazon.com/sdk-for-javascript/v3/developer-guide/javascript_ses_code_examples.html) and [SES SendEmail](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_SendEmail.html). SDK automatic send retries are disabled. SES uses attempt tags and a configured event publishing set. Unknown live sends remain unresolved until signed callbacks or provider evidence arrive; no blind resend is performed.

The callback verifies exact configured SNS topic, fixed regional HTTPS certificate origin/path, bounded certificate/body size, certificate validity and RSA signature before recording a delivery observation. It supports SNS signature versions1/2. Subscription confirmation requires the operator's configured SNS setup; the app does not follow arbitrary subscription URLs. Reference: [AWS SNS signature verification](https://docs.aws.amazon.com/sns/latest/dg/sns-verify-signature-of-message-verify-message-signature.html).

Routes include each portal's `/notifications` inbox, `/admin/notifications-operations`, strict `/api/v1/notifications` reads/commands and `/api/webhooks/email`. The admin screen supports current staff queue assignment, status filtering, failed-delivery retry and unknown-delivery reconciliation. Browser verification is pending at this entry.
