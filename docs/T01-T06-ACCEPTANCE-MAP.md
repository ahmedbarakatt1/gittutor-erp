# T01–T06 acceptance assertion audit

Static review dated 2026-11-13. This maps all **81 catalogue cases owned by T01–T06**, including all **29 original source cases** in those tasks. The other original source cases belong to later tasks. Source: `fixtures/acceptance-cases.json`; the catalogue's proposed `test_file` is not treated as evidence when the file does not exist or its assertions differ.

This audit read test bodies, fixture setup where material, and assertions. It did **not run tests**, change catalogue execution statuses, or establish a release pass. “Direct” below means an explicit assertion was found, not that it passed. “Partial” identifies a narrower existing assertion. “Gap” means no direct assertion of the stated behavior was located in the reviewed test tree. Root's recorded release execution remains authoritative. Files added or changed after this review need their own reconciliation.

Paths below are relative to the repository. `I/` means `tests/integration/`, `U/` means `tests/unit/`, and `B/` means `tests/e2e/`. Quoted names identify actual test declarations; parameterized names retain their placeholders. A related test is recorded explicitly as partial evidence rather than substituted for the acceptance requirement.

The 19 November follow-up executed GT-1403 and GT-1405 on the disposable synthetic database. The updated rows below give the results. [Execution command and release criteria](handoff/03-operations-and-release.md)

## Material checkpoint gaps

The T04–T06 integration checkpoint cannot be advertised as literal catalogue completion from the existing tests alone:

- T04: no direct final **confirmed private** slot race (GT-201); late settlement after an expired seat is resold (GT-205); retained meeting access for the remaining group after one cancellation (GT-206); the exact three-confirmed-seat capacity-reduction HTTP409 (GT-207); two staff reschedule commits with loser reload (GT-303); fully funded three-to-four amendment commit (GT-1207); or confirmed-booking versus availability-edit race (GT-1609). Existing hold, schedule, amendment, and worker tests cover substantial mechanics but not these complete scenarios.
- T05: exact full 50000 package recognition on duplicate completion (GT-1305), exact 72500→36250 partial tutor fee (GT-1308), completion_pending behavior without an approved partial decision (GT-1309), renewed-label obligation reporting (GT-1313), and cancellation versus qualified completion race (GT-1317) are not directly demonstrated by the located assertions. Full value-mode 57500 recognition plus both original-value refund boundaries in GT-1318 also remains partial.
- T06: no exact replacement-policy three 5000 customer debits plus -10000 tutor adjustment test (GT-1209). Some receipt and claim variants remain partial or absent, including GT-504/505/508, actionable ambiguous matching (GT-1406), account/channel-separated external-ID reuse (GT-1407), and the exact 50000+50000 one-transfer split (GT-1409).
