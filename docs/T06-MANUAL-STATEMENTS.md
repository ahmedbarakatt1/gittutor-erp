# Manual statement adapter

The initial InstaPay/Vodafone Cash adapter consumes independently sourced statements and creates **pending candidates only**. A current authorized reviewer separately verifies settlement and actual payer ownership. Parsing never allocates money or confirms a booking.

The normalized CSV input has exactly four headers, in any order: `external_id,amount_minor,currency,observed_at`. Amounts are positive integer EGP minor units up to the JavaScript safe-integer boundary; currency is exactly `EGP`; timestamps include an explicit UTC offset. The declared statement period contains inclusive Africa/Cairo business dates, checked separately from the normalized UTC instant. Native provider layouts require explicit normalization into this documented format; the adapter does not guess bank columns or decimal units.

Quoting follows [RFC4180](https://www.rfc-editor.org/rfc/rfc4180); LF and CRLF records and an optional UTF-8 BOM are accepted. The parser checks original-byte SHA256 before decoding and uses fatal UTF-8 decoding. Limits are25MiB,10000 data rows,16 parser columns and4096 characters per cell; the application schema then requires exactly four fields. Malformed, duplicate-reference, invalid-amount, wrong-currency and out-of-period rows produce a whole-import review result with zero candidates. No raw cell or exception text enters the safe failure code. PDF remains `requires_manual_review`.

The restricted worker receives `statement_import_requested` / `payments.validate_statement`, aggregate importID and exactly `{import_id}`. Its stable processing key is `statement-import:<job UUID>`. Private prepare/finalize functions pin the immutable file version/hash, import version and receiving account. SQL independently validates the whole candidate batch and deduplicates the receiving-account/channel/external identity. A committed result is replayed before reading or importing again after a lost acknowledgement.

T06 synthetic metadata contains no uploaded bytes. The default reader returns no content and records `awaiting_file_bytes`, without claiming scanning or parsing succeeded. T07 supplies the private bounded immutable Storage reader and enqueues a fresh validation job when bytes become available; old per-job results remain immutable. Actual read failures record `failed/FILE_READ_FAILED`; byte-size/hash discrepancies require review. Unknown database outcomes use the durable outbox reconciliation path. No external payment provider credential is required for this manual adapter.
