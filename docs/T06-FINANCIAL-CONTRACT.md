# T06 financial integration contract

2026-11-11. Consolidates root decisions, tooling's Q1/Q2 amendment analysis and the DB core proposal. T05 passed and was committed before T06 implementation began. This contract defines the shared database, server and UI boundaries; execution evidence is recorded separately in IMPLEMENTATION-STATUS.md.

## 1. Fixed conventions and ownership

UUID IDs; UTC instants supported by existing booking validators; EGP safe integer minor units; exact numeric intermediates. Mutable aggregate versions are positive int32. All public mutations take `p_idempotency_key text`; versioned mutations additionally take `p_expected_version integer`. `C={command_id,resource_id,version}`. Creation201, replay/ordinary update200, durable worker import202. All public DTOs are strict allowlists, no-store and customer-safe by default.

DB owns finance/evidence/review/refund tables, source locks, journal/adjustment/allocation/refund primitives, payment RPC/read dispatcher and SQL tests. Tooling owns booking/package funding attachment, confirmation/amendment/cancellation integration and their SQL tests. Root owns payment TS/HTTP, encryption/artifact transport, manual adapter/worker and durable docs. UI owns portals/browser tests. Each owner generates a complete new migration; no competing edits to applied dispatchers.

DB also owns statement-import headers/candidate provenance and narrow worker prepare/finalize RPCs; root owns the manual statement parser/adapter and worker. Freeze their exact signatures together at T06 start before dependent implementation. `create_statement_import` enqueues purpose `payments.validate_statement` with import ID as aggregate and payload `{import_id}`. Parsing clean immutable CSV bytes can create pending candidates only, deduplicated by stable receiving account/channel/external ID; it never verifies settlement. PDF remains visible `requires_manual_review`. T06 synthetic metadata without bytes explicitly awaits T07; a guarded fake-byte fixture may exercise real parser/recovery but is never represented as live uploaded evidence. No undefined positive-success stub.

Core monetary helpers live in `finance_private`; booking/package helpers remain `app_private`. Only `api` is exposed. Commands owner stays NOLOGIN/NOBYPASSRLS with empty search_path and RLS access. No additional anonymous RPC. Only exact artifact/import worker functions receive worker EXECUTE. Public commands derive current actor/session, validate role/scope before replay and recheck authority under locks before posting.

Common immutable source columns, abbreviated `I`: `id uuid PK,actor_account_id uuid nullable,command_id uuid,source_line_key text,effective_at timestamptz,recorded_at timestamptz`; unique command/line where applicable. Common mutable aggregate columns `V`: `id uuid PK,version int default1,created_at,updated_at`. Restrictive FKs; financial/evidence/acceptance history is append-only. Cached lifecycle fields never replace primary ledger facts.

## 3. One lock order

Current Auth/role/relationship locks precede domain locks. Discover complete scope, then sorted tutors → occurrences → enrollments → sorted cases → receipts/evidence → sorted learner financial mutexes → purchases → lots → entitlement reservations/consumption/remedy sources → charge_accounts → incoming_transfers → credit lots/reservations → refund headers/attempts → destination/version/artifact.

Case replacement/claim ends at its level. Pure settlement/ownership binding only uses receiving-account immutable evidence, transfer and credit locks, never later booking. Pure destination verification ends at destination/artifact and must not acquire an earlier money/booking lock. Reads use immutable source/evidence joins without mutation locks; a read endpoint doing an explicit authoritative preview may hold already ordered booking/financial locks but cannot mutate financial history.

Commands spanning several enrollment updates prelock the union of affected learners once, sorted. Source graph discovery is rechecked after locks; if a new allocation introduced an earlier-order resource, abort `RETRYABLE_CONFLICT` before writes and rediscover. Never catch an arbitrary DB error as an ordinary unmet confirmation condition.

An amendment earmark requires the current CS/admin claim when source credit is reserved. Its immutable provenance records that owner/claim/evidence. Later authorized amendment consumption rechecks the current committing admin, exact proposal, evidence, beneficiary authority, source-payer consent and source reconciliation; it does not require the historical CS lease to remain live. Earmark lifetime is bounded by proposal and source-intent expiry. A claim expiring after a valid reservation is not itself a revocation of customer consent.

Normal charge credits reduce unpaid debt first. Any cash excess is released proportionally across net active cash allocations using exact largest remainder and stable allocation-ID ties. Package-value applications are excluded from these weights; a lower charge than active package value requires explicit approved coverage remedy. Every released credit keeps its payer/source.

`ChargeBalance={charge_id,version,currency,original_minor,adjustments_minor:signed,commercial_net_minor,allocated_cash_minor,allocated_package_value_minor,receivable_minor:signed,refund_reserved_minor,refunded_minor,credit_released_minor,reconciliation_state:'clear'|'requires_review',recovery_exposure_minor}`.

Ambiguous bank loss remains an original-source exposure, never a guessed proportional charge debt. Affected charge reads show `requires_review`; `recovery_exposure_minor` remains0 until an explicitly attributed charge-specific recovery posting exists. Attributed allocation reversals change the normal charge receivable. Original-payer transfer and admin exception views retain the full signed source exposure. Admin exception lists calculate current actionable exposure without rewriting the original stored exception fact.

`TransferBalance={transfer_id,version,state,currency,gross_settled_minor,reversed_minor,net_allocated_minor,refund_settled_minor,refund_returned_minor,credit_converted_minor,refund_reserved_minor,unapplied_signed_minor:signed,available_minor,recovery_exposure_minor,payer_binding_id:null|uuid,payer_account_id:null|uuid,reconciliation_state}`. `unapplied_signed=gross_settled-bank_reversed-net_allocated-settled_refunds+returned_refunds-converted_credit`; operational available subtracts active reservations and is0 during unresolved exposure, while the signed balance is retained. Outgoing settled and incoming returned values are separately visible, never netted away in immutable history.

## 8. Reversal, refunds and checkpoint behavior

Unambiguous single-source reversal reverses identifiable active allocation and reopens debt. Ambiguous partial loss across learners posts cash immediately, records signed source exposure/owned exception, blocks reuse and waits for explicit admin `resolve_transfer_reversal` allocation/unapplied plan. Resolution never reposts cash. Reversal after refund retains both external effects and recovery exposure; it cannot trigger a second reimbursement.

Refunds reserve only existing source value and exact approved original benefit. Pending/unknown holds funds and benefit; verified failure/cancellation releases, settlement consumes once. A charge with several payers yields separate refunds pinned to each owner/destination. Full named coverage carrying25000/50000 never creates standalone-price debt or cash-refund eligibility from subsidy. Value mode7500/32500 remains explicit; actual top-up funding retains its own refund source.

`record_refund_reversal` handles verified partial or full incoming return of an outgoing settled refund. It locks the refund and its complete original source graph in the shared order, retains original payout/attempt/postings and appends one unique incoming journal. Returned amounts are attributed over the still-unreturned original refund source components by exact largest remainder and stable refund-source-reservation-ID tie break; totals cannot exceed any original component. Each returned credit lot retains the original payer, transfer and refund reversal. Original cash/benefit remedy remains committed: a returned refund does not restore entitlement or make that same consumption refundable twice. A new outgoing refund can reserve only this newly returned cash lot with a currently verified same-payer destination, provided source reconciliation is clear. An overlapping incoming transfer reversal keeps the returned source under reconciliation rather than inventing usable money.

DB-owned reversal tests must cover actual settled outgoing then partial/full incoming return, duplicate external identity/new key and same-key replay, cumulative over-return rejection, immutable original journal, stable per-source attribution, independent concurrent returns, no entitlement restoration/reset of original remedy limits, and return-after-source-loss with signed recovery exposure. These are separate from incoming-transfer reversal checks and require real execution before coverage claims.

T05 and T04 remain awaiting_T06 until real combined tests pass. T07 actual uploaded bytes/private storage, T08 genuine delivery/earnings and live/manual provider readiness are distinct. Guarded synthetic metadata and historical kernel fixtures are labeled evidence limits, not silently counted as complete provider/delivery cases.

## T06 statement validation worker boundary (frozen 2026-11-11)

The transaction emits `statement_import_requested`, purpose `payments.validate_statement`, aggregate equal to the import UUID and payload exactly `{import_id}`. Root's handler rejects any mismatch. Worker-only `app_private.prepare_statement_import(p_import_id uuid,p_idempotency_key text)` returns `{import_id,version,state,file:{file_id,object_key,object_version,checksum_sha256,detected_mime,byte_size,source_provenance},receiving_account_id,channel,statement_period:{from,to},completed_result:null|{state,candidate_count,duplicate_count}}`. Prepare persists processing once for the stable job key. `app_private.finalize_statement_import(p_import_id uuid,p_expected_version integer,p_checksum_sha256 text,p_state text,p_candidates jsonb,p_reason_code text,p_idempotency_key text)` returns `{state,candidate_count,duplicate_count}`. Both calls use `statement-import:${job.id}`. A terminal committed result replays unchanged after lost acknowledgement; later T07 byte availability queues a fresh validation job rather than rewriting a previous awaiting result.

Final states are completed, requires_manual_review, awaiting_file_bytes, failed or unknown. Candidate shape is exactly `{external_id,amount_minor,currency:'EGP',observed_at}`. CSV headers are exactly external_id,amount_minor,currency,observed_at in any order; UTF-8/RFC4180, 25MiB, 10000 rows, 16 columns maximum and 4096 characters/cell. The entire candidate batch is validated before any pending transfer insertion; duplicate external IDs within the batch or malformed/out-of-period rows yield no candidates. Observed instants must fall within the inclusive Africa/Cairo statement dates. Stable receiving account/channel/external ID dedup never changes an existing transfer or posts cash settlement.

Safe review codes: PDF_REQUIRES_MANUAL_REVIEW, UNSUPPORTED_FILE_TYPE, INPUT_LIMIT_EXCEEDED, INVALID_UTF8, MALFORMED_CSV, HEADER_MISMATCH, INVALID_ROW, OUTSIDE_STATEMENT_PERIOD, DUPLICATE_EXTERNAL_ID, CHECKSUM_MISMATCH, FILE_SIZE_MISMATCH. Missing bytes is awaiting_file_bytes/FILE_BYTES_UNAVAILABLE; a reader exception is failed/FILE_READ_FAILED. No raw exception or source bytes enter result/audit payloads. The worker passes the pinned metadata checksum; checksum mismatch is a review outcome, never positive evidence verification.
